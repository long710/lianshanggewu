1. 什么是交易 (Transaction)?

常见误区

很多人以为交易是“把比特币文件从我的手机发到你的手机”。

错！区块链没有“文件传输”。

本质真相

交易其实是一张**“小纸条”**。

  • 内容：“我同意从张三划走1个币给李四”
  • 动作：全网广播
  • 结果：矿工修改**全球总账本**
底层逻辑

以太坊状态机

State Machine: 交易是触发状态机翻页的唯一驱动力。

Formula:

σn+1 ≡ Υ(σn, T)

(新状态 = 旧状态 + 交易处理)

2. 交易的解剖 (Anatomy)

如果不理解结构，就永远只是看热闹。一笔原始交易数据包里，**严格包含**右侧字段。

Nonce: 防止重放的计数器
Gas: 必须支付的过路费
v, r, s: 核心数字签名
transaction.json 
{
  "nonce": 5,               // 计数器
  "gasPrice": "20 Gwei",    // 燃料单价
  "gasLimit": 21000,        // 燃料上限
  "to": "0x742d...44e",     // 接收方
  "value": "10000000",      // 转账金额
  "data": "0x",             // 附加数据
  "v, r, s": "..."          // 数字签名
}
关键字段 A

Nonce (计数器)

银行柜台排队取号，必须按 1号、2号、3号顺序办理。

防止重放攻击 (Replay Attack)

如果你给朋友转了10块钱，黑客截获数据包想广播100次把你的钱扣光？
不可能。
网络会检查："Nonce 0 刚才已经处理过了，这个数据包无效。"

严格顺序执行

如果 Nonce 0 因为给的小费太少卡住了，那么你发出的 Nonce 1, 2... 全部会在后面排队。
必须先处理完 0，才能处理 1。

Nonce 0 (Done)
Nonce 1 (Processing)
Nonce 2 (Waiting)
关键字段 B

Gas (燃料)

以太坊是“世界计算机”。占用全球矿工的硬盘和算力，必须交**过路费**。

  • 防止死循环攻击 (`while(true)`)
  • EIP-1559 机制：基础费销毁 + 小费给矿工

费用去向 (EIP-1559)

Base Fee (销毁/Burn)
+
Priority Fee (小费)
关键字段 C

v, r, s (数字签名)

不需要看你的私钥（印章戒指），只看信封上的红印（签名）。

SIGNED

生成签名 (你的钱包)

Sign( Keccak256(数据), 私钥 ) = {v, r, s}

验证签名 (矿工)

Recover( {v, r, s}, 数据 ) == 发送者地址

整个过程完全不需要你的私钥联网。
